## 1. Đánh giá chung

**Điểm mạnh (mức trên trung bình rõ rệt):**

- Kiến trúc tách tiến trình đúng hướng: main / Session Host (utilityProcess) / renderer sandbox.
- Mọi IPC đều kiểm sender và validate bằng zod.
- Electron fuses được cấu hình chặt.
- Vault chuẩn: Argon2id + XChaCha20-Poly1305, AD gắn theo bảng/id/trường, mô hình DEK/KEK.
- Migration có transaction, backup trước khi chạy, phát hiện được schema mới hơn.
- Không có command injection: các lệnh đều dùng argv và `shellQuote`. K8s dùng client HTTP riêng, không gọi kubectl.
- Host key dùng TOFU, chặn `@revoked`, xác nhận lại khi key đổi.
- Test đa tầng: unit, integration, fuzz, compat với ma trận OpenSSH, e2e, soak, package.

**Điểm yếu lặp lại ở nhiều module:**

1. **Session Host tin renderer quá nhiều.** `localPath`, cờ `readOnly`, `files.editor`… đều do renderer tự khai báo. Nếu renderer bị XSS thì thành đọc/ghi file tùy ý, thậm chí RCE.
2. **Chế độ "read-only" không thật sự chỉ đọc.** Docker và K8s vẫn cho exec/shell vào container/pod.
3. **Race khi đổi ngữ cảnh** (đổi thư mục, đổi context): không có request id, response cũ có thể đè response mới.
4. **Thao tác nguy hiểm không nhất quán.** Nhiều chỗ dùng `window.confirm`/`window.prompt` gốc, có chỗ không hỏi lại gì.
5. **File quá lớn**: CreateResource 2713 dòng, K8sView 1955, DockerView 1795, Sidebar 1240, controller 1180.
6. **Không có Error Boundary nào** ✔: một module lỗi khi render là trắng toàn bộ app, mất mọi phiên đang mở.
